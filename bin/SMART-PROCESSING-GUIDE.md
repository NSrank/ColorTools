# ColorTools 智能处理指南

本指南介绍了 ColorTools 插件的最新智能处理功能，专门解决颜色泄露和语言适配问题。

---

## 🎯 **解决的问题**

### 问题1：颜色泄露
**现象**：整个死亡信息都变成了蓝色
**原因**：颜色代码影响了后续的所有文本
**解决方案**：智能颜色范围控制，自动添加颜色重置

### 问题2：语言适配
**现象**：死亡信息只能显示英语
**原因**：重新处理Component时丢失了翻译信息
**解决方案**：保留翻译组件结构，只处理参数中的颜色代码

---

## 🔧 **新版本特性**

### 1. **智能Component处理**
- **保留翻译结构**：检测并保留 `TranslatableComponent`
- **精确处理参数**：只处理翻译参数中的颜色代码
- **递归处理子组件**：智能处理复杂的Component树

### 2. **精确颜色控制**
- **防止颜色泄露**：自动在颜色文本后添加重置代码
- **精确范围匹配**：只影响指定的文本部分
- **支持多种格式**：`&#rrggbb&`、渐变色等

### 3. **双重处理策略**
- **智能处理优先**：尝试保留原始结构
- **传统处理备用**：确保兼容性

1. **停止服务器**


4. **启用调试模式**
   ```bash
   /colortools debug on
   ```

## 🔍 **问题诊断**

### 如果颜色仍然泄露

#### 检查调试日志
1. **确认颜色重置**：查看是否添加了 `&r`
2. **检查处理范围**：确认颜色代码的匹配范围

#### 可能的解决方案
```bash
# 测试特定的颜色格式
/colortools testcolor &#55B1C2&测试文本&#ff0000&其他文本

# 检查MineDown处理
/colortools test &#55B1C2&测试&r正常文本
```

### 如果语言仍然是英语

#### 检查翻译组件
1. **确认组件类型**：查看是否检测到翻译组件
2. **检查参数处理**：确认参数是否正确处理

#### 可能的解决方案
```bash
# 检查客户端语言设置
# 确认服务器支持多语言
# 测试其他翻译消息
```

### 如果出现处理错误

#### 查看错误日志
```bash
tail -f logs/latest.log | grep "处理Component时发生错误"
```

#### 常见错误和解决方案
1. **API兼容性问题**：检查Paper版本
2. **MineDown处理失败**：检查颜色代码格式
3. **Component结构问题**：使用传统处理方法

## 🎯 **高级配置**

### 调整颜色重置策略

如果需要自定义颜色重置行为，可以在配置中添加：

```yaml
# config.yml
minedown:
  auto-reset-colors: true      # 自动添加颜色重置
  preserve-translations: true  # 保留翻译结构
  smart-processing: true       # 启用智能处理
```

### 调试级别设置

```yaml
# config.yml
settings:
  debug: true
  verbose-logging: true        # 详细日志
  component-debug: true        # Component调试
```
