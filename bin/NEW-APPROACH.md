# ColorTools 全新实现方式

本文档介绍了 ColorTools 插件的全新实现方式，采用**后处理策略**来彻底解决颜色和翻译问题。

---

## 🤔 **问题反思**

### 之前方法的根本问题
我们一直在同一个思路上打转：
- ❌ **在事件中直接修改Component** → 破坏原始结构
- ❌ **试图保留结构的同时处理颜色** → 产生矛盾
- ❌ **复杂的递归处理** → 引入更多问题

### 核心矛盾
- **处理颜色代码** vs **保留翻译结构**
- **修改Component** vs **保持原始性**
- **实时处理** vs **结构完整性**

---

## 💡 **全新思路：后处理策略**

### 核心理念：**时间分离**
1. **让原始事件正常完成** → 保留所有翻译和结构
2. **延迟1tick后处理** → 获得完整的最终消息
3. **取消原始消息，重新广播** → 完全控制输出

### 技术实现
```java
// 新策略：后处理 + 重新广播
@EventHandler(priority = EventPriority.MONITOR)  // 最后执行
public void onPlayerDeath(PlayerDeathEvent event) {
    // 延迟处理，让其他插件先完成
    scheduler.runTaskLater(plugin, () -> {
        Component original = event.deathMessage();
        Component processed = postProcessComponent(original);
        
        if (processed != original) {
            event.deathMessage(null);  // 取消原始消息
            broadcastToAll(processed); // 重新广播处理后的消息
        }
    }, 1L);
}
```

## 🎯 **技术细节**

### 后处理算法
```java
// 新的边界检测算法
result = result.replaceAll(
    "(&#[0-9a-fA-F]{6}&)([^&#§]*?)(?=\\s|$|[^a-zA-Z0-9\\u4e00-\\u9fff])", 
    "$1$2&r"
);
//  ^颜色代码^    ^文本内容^   ^边界检测：空格|结尾|非字母数字中文^
```

### 边界检测说明
- `\\s` - 空格字符
- `$` - 字符串结尾
- `[^a-zA-Z0-9\\u4e00-\\u9fff]` - 非字母数字中文字符
- `\\u4e00-\\u9fff` - 中文Unicode范围

### 重新广播机制
```java
// 取消原始消息
event.deathMessage(null);

// 手动广播给所有玩家
for (Player player : server.getOnlinePlayers()) {
    player.sendMessage(processedMessage);
}

// 发送到控制台
server.getConsoleSender().sendMessage(processedMessage);
```
